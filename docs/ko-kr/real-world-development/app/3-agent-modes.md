프로젝트에 작은 기능을 추가하는 것으로 시작했습니다. 더 큰 변경에는 더욱 체계적인 프로세스가 필요합니다. GitHub Copilot app은 조직의 기존 작업 흐름에 맞춰 필요한 기능을 올바른 방식으로 구현하도록 지원합니다. 이 레슨부터 여러 레슨에 걸쳐 일반적인 에이전트 기반 개발 프로세스를 따릅니다. 이슈에서 시작해 새 기능을 만들고, 코드가 유효하며 기능이 예상대로 작동하는지 확인한 뒤 프로젝트에 병합합니다.

> [!NOTE]
> 기능 작업을 계속하는 동안 동일한 세션을 사용합니다. 일반적으로 작업하는 파일 유형에 따라 세션이나 PR을 나누지만, 이 워크숍에서는 핵심 개념에 집중할 수 있도록 일부 단계를 간소화합니다.

이 레슨에서는 다음을 수행합니다.

- GitHub 이슈에서 새 에이전트 세션을 시작합니다.
- **Plan** 모드에서 요구 사항을 정의합니다.
- **Autopilot** 모드로 새 기능을 구현합니다.
- 코드를 검토합니다.
- 브라우저 캔버스에서 기능을 직접 확인합니다.

이후 레슨에서는 리포지토리 지침을 업데이트하고 기존 quality-checks 스킬을 사용자 지정하고 MCP 검증을 추가하고 QA 에이전트를 만든 뒤 기능 PR을 엽니다.

## 시나리오

Tailspin Toys의 카탈로그가 커지면서 방문자가 카테고리와 퍼블리셔를 기준으로 게임을 좁혀 볼 수 있어야 합니다. 백로그 이슈에 기능이 설명되어 있지만, 카테고리 조합 방식과 같은 세부 사항은 코딩 전에 합의해야 합니다. Plan 모드에서 이러한 사항을 결정한 뒤 Autopilot으로 범위가 정해진 구현을 승인합니다.

## 배경

AI 코딩 에이전트를 개발 작업 흐름에 추가해도 기본 원칙은 바뀌지 않습니다. 오히려 더 중요해집니다. 대부분의 개발자는 다음과 비슷한 과정을 따릅니다.

1. 수행할 작업을 설명하는 등록된 이슈를 엽니다.
2. 구현할 작업을 계획합니다.
3. 코드를 작성하고 검토합니다.
4. 테스트를 실행해 코드를 검증합니다.
5. 새 기능을 직접 확인합니다.
6. 풀 리퀘스트(PR)를 만듭니다.
7. 코드를 검토하고 지속적 통합 프로세스가 성공하면 병합합니다.

> [!NOTE]
> 구체적인 절차는 팀과 조직에 따라 다르지만 대체로 위 과정과 비슷합니다.

이러한 표준 접근 방식을 따르면 AI가 생성한 코드가 요구 사항을 충족하고 사람이 작성한 코드와 동일한 검토 과정을 거치게 됩니다.

## 세션 모드

**세션 모드**는 에이전트의 자율성 수준을 제어합니다. 프롬프트 필드 아래의 드롭다운에서 설정하고 언제든지 변경할 수 있습니다.

- **Interactive**: 사용자와 에이전트가 함께 작업합니다. 에이전트는 변경을 제안하고 진행하기 전에 사용자의 입력을 기다립니다.
- **Plan**: 에이전트가 먼저 계획을 작성합니다. 에이전트가 실행하기 전에 계획을 검토하고 승인합니다.
- **Autopilot**: 에이전트가 입력을 기다리지 않고 코드를 작성하고 테스트를 실행하며 자율적으로 반복합니다.

Plan 모드에서 시작해 계획을 검토한 뒤 Autopilot으로 구현합니다.

## 이슈에서 세션 시작

시작하기 전에 별점 PR이 병합되었고 로컬 `main`이 최신 상태인지 확인합니다.

1. 사이드바의 **Sessions** 아래에서 Tailspin Toys 리포지토리 폴더를 선택한 다음 리포지토리 위쪽 탐색 메뉴에서 **Issues**를 선택합니다. **Allow users to filter games by category and publisher** 이슈를 엽니다. 이 이슈는 템플릿에서 미리 생성되었으므로 새 이슈를 만들 필요가 없습니다.
2. **New session**을 선택하고 업데이트된 `main`을 기반으로 하는 **new working tree**를 선택합니다.

    ![New session 버튼을 화살표로 가리키는 GitHub Copilot app 이슈 보기](../../../_images/app-new-session-from-issue.png)

3. 이슈가 세션에 연결되었는지 확인하고 모드 선택기에서 **Plan**을 선택합니다.

> [!NOTE]
> Node.js 또는 npm을 찾을 수 없다고 표시되면 에이전트에 `node --version`과 `npm --version`을 실행하도록 요청합니다. 터미널에서는 명령이 작동하지만 세션에서 작동하지 않는다면 앱의 PATH 또는 버전 관리자 설정을 확인한 다음 앱을 완전히 종료하고 다시 엽니다. 실패한 작업과 검사를 다시 시도합니다. 에이전트가 명령을 찾지 못한다는 이유만으로 npm을 다시 설치하지 않습니다.

## 필터링 기능 계획

계획을 세우면 Copilot이 코드를 작성하기 전에 구현 방식을 검토할 수 있습니다. 이슈에서 세션을 시작했으므로 Copilot은 기능 요청을 이미 파악하고 있습니다. 다음 프롬프트를 보냅니다.

```plaintext
Build this feature.
```

Copilot의 질문에 답하고 계획을 이슈의 수락 기준과 비교합니다. 계획에 카테고리 및 퍼블리셔 필터링, 접근성 있는 컨트롤, 데이터 액세스 변경, 테스트가 포함되는지 확인합니다. 여러 카테고리를 조합하는 방식이나 일치하는 게임이 없을 때의 동작처럼 불명확한 사항을 논의합니다.

계획에는 프로젝트의 기존 도구를 사용하는 린트, 단위 테스트, E2E 테스트, 타입 검사가 포함되어야 합니다. 필터링 구현과 테스트에 집중하고, 품질 작업을 마친 뒤 PR을 만듭니다. 계획을 승인하기 전에 필요한 수정을 요청하고 나중에 검증할 때 사용할 이슈 URL과 합의한 내용을 기록해 둡니다.

## Autopilot 명시적으로 승인

계획에 동의하면 **Approve and implement this plan** 또는 사용 중인 버전에서 같은 의미로 표시되는 옵션을 선택합니다. 승인하면 모드가 바뀐다고 가정하지 말고 현재 모드를 확인합니다. 모드 표시기에 **Autopilot**이 표시되어야 합니다.

Copilot은 구현을 시작하고 수립된 계획에 따라 코드를 작성하고 테스트를 실행하며 작업을 반복합니다.

> [!NOTE]
> 승인하면 구현이 바로 시작될 수 있으므로 먼저 계획을 검토합니다. Copilot이 종속성 누락이나 포트 충돌을 보고하면 검사가 완료된 것으로 처리하기 전에 설정 문제를 해결합니다. 직접 시작한 서버만 중지합니다.

## 구현 검토 및 확인

생성한 코드는 다른 코드와 마찬가지로 병합 전에 검토해야 합니다.

1. **Changes**를 열고 필터링 구현과 테스트를 살펴봅니다.
2. 여러 카테고리 및 퍼블리셔 조합을 포함해 결과를 이슈와 승인한 세부 사항에 비교합니다. 변경 내용이 기존 리포지토리 지침을 따르는지도 확인합니다.
3. 린트, 단위 테스트, E2E 테스트, 타입 검사의 결과를 확인합니다. 검사를 건너뛰었다면 통과가 아닙니다.
4. 구현을 수락하기 전에 실패를 해결하고 관련 검사를 다시 실행합니다. Playwright E2E 구성은 미리 보기를 빌드하고 제공하며 로컬 서버를 재사용할 수 있습니다. 테스트한 서버가 이전 레슨이 아니라 이 워크트리에서 시작한 서버인지 확인합니다.

## 새 기능 살펴보기

코드가 괜찮아 보여도 실제로 실행되는지 확인해야 합니다. 이전처럼 사이트를 시작하고 브라우저 캔버스에서 엽니다.

1. 다음 프롬프트로 Copilot에 앱을 시작하고 브라우저 캔버스에서 페이지를 열도록 요청합니다.

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. 잠시 후 앱이 시작되고 Copilot app 안에 브라우저 창이 열립니다.
3. 카테고리를 선택하고 결과가 해당 카테고리와 일치하는지 확인합니다. 필터를 지운 다음 퍼블리셔를 선택하고 결과가 해당 퍼블리셔와 일치하는지 확인합니다.
4. 카테고리와 퍼블리셔 필터를 조합해 결과를 이슈와 승인된 계획에 비교합니다. 여러 카테고리를 지원한다면 합의한 조합 방식도 확인합니다.
5. 일치하는 게임이 없는 조합을 시험하고 빈 상태를 확인합니다. 필터를 지우거나 초기화해 전체 목록이 다시 표시되는지도 확인합니다.
6. 완료하면 다음 프롬프트로 이 세션에서 시작한 개발 서버를 중지하도록 Copilot에 요청합니다.

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 다음 레슨을 위해 세션 유지

아직 필터링 PR을 만들거나 병합하지 않습니다. 레슨 4~8에서 사용할 세션, 워크트리, 브랜치를 그대로 유지합니다. 다음 레슨에서는 필터링 코드에 사용자 지정 지침을 적용한 다음 스킬과 QA를 개선하고 레슨 8에서 PR을 만들고 병합합니다. 개발 서버를 중지한 뒤 세션을 그대로 두고, 다음 레슨에서 같은 세션으로 돌아옵니다.

## 요약 및 다음 단계

여러 에이전트 모드를 사용하여 기능을 만들고 검토했습니다. 이 레슨에서는 다음을 수행했습니다.

- GitHub 이슈에서 새 에이전트 세션을 시작했습니다.
- **Plan** 모드에서 요구 사항을 정의했습니다.
- **Autopilot** 모드로 새 기능을 구현했습니다.
- 코드를 검토했습니다.
- 브라우저 캔버스에서 기능을 직접 확인했습니다.

다음으로 [사용자 지정 지침][next-lesson]을 사용해 문서화된 관행에 따라 코드를 생성하도록 안내합니다.
