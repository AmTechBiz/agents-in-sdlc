前のレッスンでは、小さな機能をプロジェクトに追加しました。しかし、より大規模な変更には、さらに堅牢なプロセスが必要です。GitHub Copilot app は組織の既存のフローに沿って作業できるように設計されており、適切なものを適切な方法で構築できます。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスを実践します。Issue から新機能を作成し、コードが有効で、機能が期待どおりに動作することを確認して、最終的にプロジェクトにマージします。

> [!NOTE]
> 機能のワークフローを続ける間は、同じセッションを使用します。通常は作業するファイルの種類ごとに異なるセッションや PR を使用しますが、ここでは主な概念に集中するため簡略化します。

このレッスンでは、次のことを行います。

- GitHub Issue から新しいエージェントセッションを開始します。
- **Plan** モードで要件を決めます。
- **Autopilot** モードで新機能を実装します。
- コードをレビューします。
- ブラウザーキャンバスで機能を手動で検証します。

この機能の作業を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増えているため、訪問者がカテゴリや発行元でゲームを絞り込めるようにします。バックログの Issue には機能が記載されていますが、カテゴリを組み合わせる方法などはコーディング前に合意が必要です。Plan モードで判断を決めてから、Autopilot に範囲を限定した実装を許可します。

## 背景

AI コーディングエージェントを開発ワークフローに導入しても、基本は変わりません。むしろ、基本はさらに重要になります。多くの開発者は、次のような流れで作業します。

1. 必要な作業の詳細を記載した Issue を開きます。
2. 構築する内容の計画を立てます。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. pull request (PR) を作成します。
7. コードのレビューと継続的インテグレーションプロセスが成功したら、コードをマージします。

> [!NOTE]
> 正確な手順はチームや組織によって異なりますが、ほとんどの場合は上記の流れを基本にしています。

この標準的な進め方を守れば、AI が生成したコードが定められた要件を満たし、手作業で作成したコードと同じ検証プロセスを通るようにできます。

## セッションモード

**セッションモード**では、エージェントに与える自律性の度合いを設定します。プロンプトフィールドの下にあるドロップダウンから設定し、いつでも変更できます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、次の処理に進む前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。エージェントが実行する前に、計画を確認して承認します。
- **Autopilot**: エージェントが完全に自律して作業します。入力を待たずにコードを書き、テストを実行して反復します。

まず Plan モードで計画を確認し、その後 Autopilot モードで実装します。

## Issue からセッションを開始する

開始する前に、星評価の PR がマージされ、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** で Tailspin Toys のリポジトリフォルダーを選択し、リポジトリの上部ナビゲーションで **Issues** を選択します。既存の **Allow users to filter games by category and publisher** Issue を開きます。テンプレートに含まれる Issue のため、新しく作成する必要はありません。
2. **New session** を選択し、更新済みの `main` に基づく **new working tree** を選びます。

    ![GitHub Copilot app の Issue ビューで、New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. Issue がセッションに添付されていることを確認し、モード選択メニューで **Plan** を選択します。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` を実行するよう依頼します。ターミナルでは動作するのにセッションでは動作しない場合は、アプリの PATH やバージョンマネージャーの設定を確認し、アプリを完全に終了してから再度開きます。失敗した操作とチェックを再試行してください。エージェントが見つけられないという理由だけで npm を再インストールしないでください。

## 絞り込み機能を計画する

計画を立てることで、Copilot がコードを書く前にアプローチを確認できます。Issue から開始したため、Copilot は機能の依頼をすでにコンテキストとして持っています。次のプロンプトを送信します。

```plaintext
Build this feature.
```

Copilot の質問に回答し、Issue の受け入れ条件と計画を照らし合わせます。カテゴリと発行元による絞り込み、アクセシブルなコントロール、データアクセスの変更、テストが含まれていることを確認してください。複数のカテゴリを組み合わせる方法や、一致するゲームがない場合の動作など、不明確な点を話し合います。

計画には、プロジェクトの既存ツールを使った lint、ユニットテスト、E2E テスト、型チェックを含めます。絞り込み機能の実装とテストに範囲を絞ります。品質ワークフローが完了してから PR を作成します。計画を承認する前に修正を依頼し、後から検証するために Issue の URL と合意内容を控えておきます。

## Autopilot を明示的に承認する

計画に納得したら、**Approve and implement this plan** または使用中のバージョンに表示される同等のオプションを選択します。承認しただけでモードが切り替わると思い込まず、アクティブなモードを確認します。モード表示が **Autopilot** になっていることを確認してください。

Copilot は実装を開始し、計画に沿ってコードを生成し、テストを実行しながら作業を反復します。

> [!NOTE]
> 承認すると実装がすぐに始まる場合があるため、先に計画をレビューしてください。依存関係の不足やポートの競合が報告された場合は、チェック完了と判断する前にセットアップの問題を解決してください。自分が起動したサーバーだけを停止してください。

## 実装をレビューして検証する

生成されたコードも、他のコードと同じようにマージ前にレビューする必要があります。コードをレビューしてからサイトを実行し、表示を確認しましょう。

1. **Changes** を開き、絞り込み機能の実装とテストを確認します。
2. 複数カテゴリと発行元の組み合わせも含め、結果を Issue と承認した追加要件に照らし合わせます。変更が既存のリポジトリの指示に従っていることも確認します。
3. lint、ユニットテスト、E2E テスト、型チェックの出力を確認します。スキップされたチェックは成功ではありません。
4. 実装を承認する前に失敗を解消し、該当するチェックを再実行します。Playwright の E2E 設定はビルドしてプレビューを配信し、ローカルサーバーを再利用できます。以前のレッスンで起動したサーバーではなく、この worktree のサーバーがテストに使われていることを確認してください。

## 新機能を確認する

コードに問題がないように見えても、実際に動くでしょうか。前と同じようにアプリを起動し、ブラウザーキャンバスでサイトを開きます。

1. 次のプロンプトを使い、アプリを起動してブラウザーキャンバスでページを開くよう Copilot に依頼します。

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザーウィンドウが開きます。
3. カテゴリを選択し、結果がそのカテゴリと一致することを確認します。フィルターを解除してから発行元を選択し、結果がその発行元と一致することを確認します。
4. カテゴリと発行元の両方を選択し、Issue と承認した計画に照らして結果を確認します。複数カテゴリがサポートされている場合は、合意した組み合わせの動作を検証します。
5. 一致するゲームがない条件を試し、空の状態を確認します。フィルターを解除またはリセットして、全件が再表示されることを確認します。
6. 確認が終わったら、次のプロンプトを使って、このセッションで起動した開発サーバーを停止するよう Copilot に依頼します。

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 次のレッスンに備えてセッションを保持する

絞り込みの PR はまだ作成またはマージしないでください。レッスン 4 から 8 まで、このセッション、worktree、ブランチを使います。次は絞り込みコードにカスタム指示を適用し、スキルと QA の改善を追加してから、レッスン 8 で PR を作成してマージします。開発サーバーを停止した後はセッションをそのままにし、次のレッスンで再開してください。

## まとめと次のステップ

- GitHub Issue から新しいエージェントセッションを開始しました。
- **Plan** モードで要件を決めました。
- **Autopilot** モードで新機能を実装しました。
- コードをレビューしました。
- ブラウザーキャンバスで機能を手動で検証しました。
