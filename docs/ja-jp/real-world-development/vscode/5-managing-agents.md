GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集して、コマンドを実行するなど、自律的に作業します。Copilot は自分のマシンでリアルタイムに作業するため、VS Code の Copilot Chat ではツールの呼び出しやファイル編集を確認できます。差分をインラインでレビューし、変更ごとに採用または却下を選択して、エディターを離れずに追加のプロンプトを送ることで作業の改善や拡張を指示できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューし、採用します。
- 作業中のセッションにライトモードの切り替えを追加するよう指示します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントは、ハイコントラストモードを実装中です。作業中にデザインチームから新たな依頼があり、既定のテーマが暗すぎると感じるユーザーのために、ライトモードの切り替えも追加することになりました。新しく会話を始める代わりに、既存のセッションに追加の作業を指示します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調査したファイル、実行したコマンド、提案された編集を確認できます。各ファイル編集は差分と **Keep** / **Undo** の操作と共にチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りと編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインライン表示されます。
   - **Keep** を選択すると、変更を採用します。
   - **Undo** を選択すると、変更を元に戻し、エージェントに再度作業してもらいます。
4. チャットの上部にある **Files changed** の表示を開き、このセッション中にエージェントが変更したすべてのファイルを確認することもできます。

> [!NOTE]
> ツールの使用 (たとえばターミナルコマンドの実行) に許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドのみ承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、行った変更をまとめたメッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたので、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けるため、エージェントは前の作業で使ったコンポーネント、スタイルの方法、local storage のパターンなどのコンテキストを保持しています。

1. Copilot Chat の入力欄に、次のフォローアッププロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前回の変更を調べて、作業を続けながらライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集をひとつずつ確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが希望と異なる方向に進んだ場合、たとえばトグル UI を望まない方法でリファクタリングする場合は、チャット入力欄の横にある **Stop** ボタンで停止してから、追加のプロンプトで意図を伝えます。

> [!TIP]
> 進行中のセッションに指示を出す方が、最初からやり直すより短時間で済みます。フォローアッププロンプトで調整を依頼したり (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」)、方針を修正したり (「3 つ目のトグルは追加せず、既存の設定パネルにライトモードを組み込む」)、範囲を広げたり (「両方のトグルにキーボードショートカットも追加する」) できます。

## 作業ファイルをレビューする

コミットする前に、エージェントが変更したすべての内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどの更新が表示されます。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage への保存など、カスタムエージェントの指示に基づくアクセシビリティ対応を確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで、作業中のセッションを監視して指示しました。ファイルの編集をひとつずつ確認して採用または却下し、フォローアッププロンプトを送り、コンテキストを失わずに作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または却下する。
- 作業中にフォローアッププロンプトでセッションに指示する。
